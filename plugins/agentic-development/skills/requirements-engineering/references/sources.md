# Sources and attribution

The terminology baseline is Birgit Penzenstadler's CSULB CECS 542 course materials published in 2017. Her [2021 course publication](https://ceur-ws.org/Vol-2857/openre1.pdf), section 2 and Table 1, identifies the syllabus, [YouTube course](https://www.youtube.com/playlist?list=PLUgFMzuE8lQDeixpbP3s6EyQx8PiNdeQL), slides, and artifact-based assignments. The bundled grounding uses the cited teaching slides and publication; it does not claim a complete lecture-transcript extraction.

## Terminology boundary

Use the course's three AMDiRE layers: context, requirements, and system. The earlier [Mini-Guideline to Requirements Engineering](https://mediatum.ub.tum.de/doc/1107943/document.pdf), section III, describes four abstraction levels: environment, system/product requirements, logical architecture, and technical architecture. It is related background, not an interchangeable layer taxonomy. Identify the source model when relating an existing artifact to either account.

The course's [Quality Assurance lecture](https://www.slideshare.net/slideshow/requirements-engineering-quality-assurance/78079094), slide 7, uses **validation** for requirement correctness against stakeholder intention and **verification** for system fulfillment of requirements. The skill qualifies verification by its object: requirements verification includes source fidelity and specification quality; system verification checks fulfillment. Validation concerns fit to stakeholder needs. This operational vocabulary distinguishes the questions and evidence without requiring one term to carry every distinction.

## Project adaptations

Agent authorization boundaries, privacy rules, and owner inspection as skill acceptance are project rules. They are not claims about what the course universally requires. Stakeholder validation concerns the engineering requirements; owner acceptance of this skill concerns the skill itself. A system satisfaction criterion is not a skill-evaluation score. Acceptance of a consumer's work follows that consumer's applicable project rules and delegated authority.

[Source consolidation](source-consolidation.md) and [task analysis](task-analysis.md) provide agent-work procedures for preserving meaning across records and assignments, inspecting execution dependencies, and translating results. Their task structure is not a reproduction of a course assignment or document outline.

The references adapt the course to flexible existing issues, documents, and linked artifacts. Content and relationships remain explicit even when the project does not use the course's document layouts. Course examples, thresholds, and assignment quotas do not become project requirements.
