# Business case

Use this reference when the decision concerns why to undertake an initiative, which alternative merits investment, or what evidence is missing for that decision. First read any existing business case: requirements work can receive this artifact rather than create it. Elaborate only the sections needed for the assigned decision; do not invent a complete investment proposal to fill a template.

## Develop the argument

Build the business case as an argument to the decision maker. Use this report structure, elaborating each section to the depth needed for the decision:

| Report section | Work to perform and result to retain |
| --- | --- |
| Executive summary | Write last, present first. Condense the problem, considerations, resources, desired outcome, and supported return and timing into language the decision maker can understand. Preserve any uncertainty that could change the decision. |
| Problem statement | State the situation requiring action and whom it affects. Distinguish the problem from a favored solution. |
| Analysis | Explain how the situation arose and what continuing it would imply. Use evidence; examine competing interpretations before treating an explanation or projection as established. |
| Solution options | Identify plausible alternatives and describe each sufficiently for comparison. Keep the current course/no-action option visible. Record why an option was excluded. |
| Project description | For the candidate project, describe resources, budget, timeline, milestones, assumptions, dependencies, risks and responses, and how outcomes would be reviewed. Mark estimates and unknowns; specify only as far as the evidence and current decision warrant. |
| Cost-benefit analysis | Compare the alternatives, including no action, using supported costs, benefits, timing, and major risks. State the basis of estimates and limits of comparable cases. Include return on investment and total cost of ownership where meaningful and supportable. |
| Recommendations | Connect the recommendation to the comparison. Identify needed people, actions, resources, unresolved dependencies, and when the case should be reconsidered. |

Work from the problem and analysis through options and comparison before settling the recommendation. A project description can remain conditional while alternatives are being considered. Distinguish the case for investigation from the case for implementation: an attractive option with an unresolved dependency does not supply that dependency's evidence or authorization.

## Check the decision support

Check the argument: does the problem follow from the analysis; is action justified; were alternatives adequately considered; is project detail sufficient; do calculations hold; and does the comparison have supporting data? Check that the summary contains the essentials. Record stakeholder preliminary support and its scope where available; support is distinct from the owner's acceptance.

## Decision-ready comparison

Use sensitivity analysis when uncertain inputs or changed scope could alter the choice. Calculate the consequences supported by available quantities: a conditional estimate, range, incremental cost, or break-even condition. State the assumption beside the result and distinguish it from a supplier quote or an accepted forecast. Vary consequential uncertain inputs over supported cases or ranges, compare alternatives on the same basis, and identify whether or where the recommendation changes. When a switching point cannot be calculated, state the missing relationship or value that prevents it; an incomplete estimate need not prevent a useful comparison.

When a decision rule is missing, offer a reasoned candidate using the stated goals, constraints, and available observations. Identify what would support proceeding, revising, or stopping and what decision remains with the owner. Use qualitative conditions where a numerical threshold lacks a defensible basis. Mark proposed thresholds, milestones, or choices as proposals rather than supplied facts or approvals. The owner should be able to assess the proposal without first designing it themselves.

A recommendation may be to investigate, defer, or continue the current course when the evidence warrants it. Keep missing evidence and decisions explicit; do not fabricate costs, benefits, ROI or agreement. Follow [record discipline](record-discipline.md) for evidence, grants, and acceptance.
